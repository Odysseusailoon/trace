Forkscope：测量 agent 轨迹在哪里分叉

YUXI ZHENG · 2026-09 · 工作笔记 · QWEN3-8B & QWEN3.6-35B-A3B · SGLANG 确定性推理

一个 LLM agent 的行为是一个轨迹分布，任何单次运行只是从中抽的一签。我们造了一台重放仪器： 对任意决策步测量反事实结局分布 od——如果当时骰子落在别处，会发生什么。用它我们找到了锁死整个 episode 命运的单个 token、多数答案是错的 benchmark 题、模型自信走进的分叉（熵监控看不见它们），以及把成功率放大 50 倍的 thinking 开关。下面每个数字都是实测的，预注册的部分有标注。H100 部分成本约 $60，35B 复制跑在一台 DGX Spark 上。

2 · 我们测什么：结局分布 ot

"这个 token 重不重要？"不是可测的问题。可测的是：在位置 t，给定已生成的前缀，最终答案会落在哪里—— correct、某个具名错误簇、还是 no answer？这个条件分布就是 ot。放到整条生成上是一个 T×C 矩阵： T 个位置，每处一个 C 维分布，每个终点都由执行判定。

correct 上的质量 陷阱簇上的质量 其他结局

这个定义把两个形容词变成两种形状。决策分叉是阶跃：ot 先是混合，然后一步收拢成点并停在那里。 漂移是移动但从不锁定。而 o0——写下任何 token 之前的分布——就是这道题自身的成功概率， 单样本评测悄悄用一次抽签顶替的正是它（§8）。

3 · 怎么采样：在决策边界重放

录一条 episode（T=1.0，工具真执行）。在每个决策边界 d 回卷到那个精确状态，重采 K=50 条完整的反事实续写—— 工具重新执行，结局对可执行 gold 判定。结局直方图就是 od；它在哪里坍缩，命运就在哪里锁死。

续写 → 正确 续写 → 陷阱 其他 / 未作答

重放看起来是平方级开销（K × D 次完整 prefill）。有 RadixAttention 前缀共享，主干只 prefill 一次： 在 650 万 token 的重放负载上实测 99.2% 缓存命中，重放比朴素重算便宜 67–206 倍。seed 派生使复跑 bit 级一致， 本页每个数字都能重新生成。

扇形图藏着两个细节。剪点重掷不排除已录制的 token——原路完全可能被再次采到，所以 od 是无偏的 "从这里重来"分布，录制运行只是其中一次抽签。剪断也不是改写：我们从不强迫另一个 token，只是选择从哪里开始不再信任记录。 下图：同一条轨迹，剪在分叉前与分叉后——剪点落在哪里，决定质量是否还流向两边。

5 · agent 层：命运在四个 token 内焊死

任务："平均每位艺术家几张专辑"，对真 SQLite 库执行。工具 schema prime 出整数除法陷阱 （返回 1.000，不报错，0% 自愈）。在第一条 SQL 轮内逐 token 截断前缀、每处重采 20 条续写、给产出的 SQL 聚簇。 琥珀 = 陷阱簇，绿 = 正确簇，虚线 = 基线路径的 token 熵。

6 · 真题野外：BIRD 上的两个模型尺寸

同一台仪器，外部 benchmark：BIRD mini-dev 按冻结的两段规则选 10 题（先文本标准，再用 10-episode 答案众数 4–6 的不确定性筛——筛离散度，不筛对错），每题每臂 200 条，四个条件：Qwen3-8B 与 Qwen3.6-35B-A3B × thinking 关/开。先看 8B 关思考的地板——地板有结构——再看规模和 thinking 各救什么。

地板里藏着三个发现。一，intent-stall：在 schema 大的 financial 库里，最多 56% 的 episode 撞上列错误后 写"我们来看下有哪些表…"，然后在预算和轮次都还有的情况下自愿停止——宣布一个动作和执行它是可分离的两件事。 二，同一开局、不同命运：b218 上最常见的正确首条 SQL 与最常见的错误首条 SQL 逐字节相同，分叉在中盘（读结果的方式）， "分叉在哪"是题的属性。三，thinking：同权重同 seed，打开思考预算把 b39 从 1/200 正确拉到 51/200。

7 · 熵能不能找到分叉？大多数能——漏掉的才是故事

便宜的想法：只在模型犹豫的地方测量。我们在 Forking Fast 公开数据上测它（Llama-3-8B，100 题， S=200 的 ground-truth ot 网格）：按 1−pbase 给位置做门控，看 PELT 检出分叉的召回。 琥珀 = 熵门控召回，橄榄 = 随机门控 null。

门控有效：约 2× 超随机富集，召回随分叉大小上升（大分叉在 top-20% 处 0.87，top-30% 处 0.95）。 两级仪器——先熵筛、只在过门的位置重放——能把测量成本降 3–5 倍。但 13–29% 的分叉发生在模型自信的位置， 任何基于熵的监控都看不见它们。agent 数据说明了这为什么要命：骰子落地之后，§5 的陷阱路径在近零熵下运行， 自信地走向注定的失败。

8 · 用分叉分布做更公平的评测

单样本评测给一个随机变量打一次分。两个实测 case 说明它怎么撒谎：schema 陷阱题上，众数答案簇是错的 （46% 陷阱 vs 18% 正确），greedy 和多数投票都在奖励错误；BIRD b226 上，模型是一枚真硬币（o0 = 0.45）。

correct 质量 众数错误簇 其他结局

分布式替代方案是一份脆性档案：带置信区间的成功概率 o0、命运锁死在哪一步、自愈率、 正确策略的覆盖度。它比 pass@1 费样本，但同一批 rollout 同时提供了 §3–§6 的归因，前缀缓存付掉了大部分账单。 在众数是错的题上，任何信任众数的评测都在奖励陷阱——self-consistency 也一样。

9 · 引擎盖下的统计

三块零件保证上面每张图诚实：分支样本怎么变成合法的 iid 抽签，平滑怎么借力而不抹掉它要找的分叉， 以及怎么知道估计已经贴上采样噪声定下的地板。

混合抽签（mixture draws）。一个剪点的原始数据是分层的：若干分支各带权重、各有 S 条续写。 下游要跑的一切——1/√S 收敛检查、跨 run 锚定——都假设数据是同一个 multinomial 的 iid 抽签，分层样本不是。 所以先混合：按权重抽一个分支，从中取一条没用过的续写，重复 S 次。混完的抽签条件 iid 服从 Multinomial(ot)， 标准检验全部合法。这是人口普查的老技巧：分层抽样之后，先按人口比例混合，再报平均。

分段平滑器（M5a）。相邻位置携带几乎相同的模型状态，借它们的样本能压噪声——但对称核会把 我们要找的那个阶跃抹平。M5a 先分段（PELT 变点检测），再在段内平滑，核在每个边界处硬截断：A 段永不漏进 B 段。 验证：22/22 合成检验恢复，TVD 估计误差降 36%，等效样本量 3.8×——在 §4 的漂移 case 上，它正确拒绝把 11 次摆动 中的任何一次叫成分叉。

留一重复（LRO）与噪声地板。S=20 够不够？平滑器还值不值得改？把手里的池子切开：20 条进估计， 其余当伪 ground truth，轮换，平均 TV 差就是 S=20 的典型误差——不花新 GPU。再让一个知道真 ot 的 oracle 在同一协议下打分：它的 TV 就是 multinomial 噪声定下的地板。贴着地板的估计器无法靠建模改进，只能加样本。 replicate-TVD 按 1/√S 收缩，实测斜率 −0.493，理论 −0.5。

链条比零件重要：定义（§2）说清估计的对象，混合让检验合法，识断的平滑把信号从 S=20 的噪声里捞出来， 地板告诉你什么时候停止调模型、开始买样本。每一块都是标准技术，工作量在把它们装到一个新对象上。
